# DOMA GeeVee CRM prototype: working brief

Read this fully before touching code. Keep replies and UI text free of em dashes and en dashes (the build refuses them).

## What this is
A single-file HTML prototype of Collings Real Estate's new CRM (DOMA) with an AI assistant (GeeVee). The current CRM the agents use today is captured as 168 static screens in `Downloads/crm-fe-screens-2026-11-13 (1).zip` (extracted copy may exist in the session scratchpad under `crm-screens/`; `data/specs.json` in this folder is a structured extract of every screen: title, tabs, filters, fields, buttons, empty states). The new CRM is built on top of that CRM: same jobs, same records, GeeVee doing the work.

## Build
- Source: `src/`. Base app: `base/DOMA_GeeVee_Desktop_CRM_V2_1_base.html` (do not edit).
- `node build.js <outputPath>` injects `src/cw*.css` into `<head>` and `src/*.js` in the ORDER list in `build.js` just before the app's final `render();})();`. It syntax-checks the result with Node and refuses any file containing an em or en dash, or the strings `</script` or `</body` (escape as `<\/body>` inside strings).
- Never build to `Downloads` yourself. Build to your own test path in the scratchpad and test there. The lead merges and ships.
- `CW_ONLY=cw-p-x.js,cw-p-y.js node build.js <out>` builds core + dashboard + boot + the named modules only.

- `src/cw-core.js`: page framework. `cwPage(pattern, {title, group, render(ctx), ai(ctx), wide?, noAI?, bare?})`, routes are hash routes (`#/contacts/C-1001?tab=notes`), `ctx={path,params,q,route}`. `cwOn(actionName, fn)` registers a button action (`data-action`), `cwModalDef(name, fn)` + `cwModal(name,arg)` for dialogs (`ui.modal={type:'cw',name,arg}`), `cwConfirm(...)`. Components: `cwHeader(title,sub,actions)`, `cwBtn(label,act,id,cls)`, `cwGoBtn(label,route,cls)`, `cwLink`, `cwStats([[label,value,foot,cls]])`, `cwCard(title,body,extra)`, `cwEmpty(title,body,actions)`, `cwNote(html,cls)`, `cwTable(key, cols[[label,cell(row),sortVal?]], rows, {select,bulk,empty,size})`, `cwTabs(key,[[v,label,count]])`, `cwTab(key,def)`, `cwPills`, `cwInput(key,ph,o)`/`cwSelect`/`cwCheck`/`cwSwitch` (bound to `cwF(key,def)`/`cwSetF`), `cwForm(fid, fields, values, {sections})` + `cwRead(fid, fields)` (validates, returns null on error), `cwKV`, `cwKanban`, `cwAI(items)` panel items `{k:'auto'|'draft'|'check'|'info'|'call', t, b, a:[[label,action,id,cls]]}`. Helpers: `cwId(prefix)`, `cwDate`, `cwDateTime`, `cwLocalDay`, `cwMoney`, `cwShort`, `cwPersist(msg)`, `cwGo(route)`, `CW_GROUPS`, `CW_ROUTES` (find a route by `pattern` to wrap its `def.render`/`def.ai`).
- `src/cw-data.js`: `cwEnsure()` seeds `state.cw` once (agents, enquiries, db, developments, relisting, sales, cma, comms, esign, docs, kpi, settlements, sessions, tickets, notifications, events, openHomes, settings, profile...). `cwPX(p)` and `cwDX(d)` lazily add CRM fields on a contact (`p.cw`) and property (`d.cw`): beds, baths, cars, type, status, priceLow/High, docs{pps,contract,lease,report,other}, photos, notes, comps, priceEvents, activity, agents, owners... `cwAddPerson(o)` (dashboard module), `cwLdNewDeal(o)` and `cwLdSetStage(d,stage,why)` (leads module), `cwContactHistory(p,what)`, `cwPropActivity(d,what)`, `cwOptedOut(p)`, `cwAgents()`, `cwProps()`, `cwContacts()`, `cwPrice(d)`, `cwAddr(d)`, `CW_ME` ('Caleb Richards'), `CW_NEAR`, `CW_POSTCODES`.
- Page modules `src/cw-p-*.js` (dashboard, properties, leads, prospecting, contacts, comms, esign, performance, admin, public, merge, rules, journey, journey2, more) and `src/cw-boot.js`. Each module prefixes its own functions, actions, modal names and cwF keys (cwPr, cwLd, cwPs, cwCt, cwCm, cwEs, cwPf, cwAd, cwPu, cwJn...). New state collections are created lazily inside the module that owns them.
- `src/cw-p-merge.js` defines the 7 navigation groups and CW_CLUSTERS (merged pages shown as tabs). `src/cw-p-rules.js`: 24-hour seller-lead rule, dashboard folded into Today. `src/cw-p-journey.js` + `journey2.js`: the appraisal-to-listing journey (call transcript or dictated recap -> GeeVee books, prepares the pack, fills the authority (A3), vendor signs on `/esign/sign/:id`, listing created, photographer booked at `/supplier/:token`, photos delivered, go-live checklist, published). ## Product rules (decided by Simon, the product owner)
- Anything that leaves DOMA (text, email, signing request, publishing) goes to Today as an approval via `addAction` (A2; contracts, authorities and publishing A3). GeeVee sends on its own only when replying to an enquiry it can answer fully from verified records. Supplier bookings are routine (A1) and logged.
- New seller leads are always a call from the agent. GeeVee drafts and sends nothing to them. 24-hour rule: call within 24 h, reminder at 20 h, escalation to the principal at 24 h.
- Internal work from a conversation (records, calendar, documents, tasks) is applied at once with Undo on a "What I did" card.
- Opted-out and do-not-contact people never get marketing. Spam Act: sender identified, unsubscribe on every marketing message.
- Victoria: Property Price Statement (not "Statement of Information"), three comparable sales, price range at most 10% wide and not below the estimate, vendor ID sighted (AML/CTF) before go-live, sold price published within 7 days of unconditional, reserve disclosed as a single figure 7 days before auction.
- Never call the database "registered buyers". Plain, direct UI text. No em or en dashes. No filler words.
- Every button must do something real; forms validate; changes persist (localStorage).
